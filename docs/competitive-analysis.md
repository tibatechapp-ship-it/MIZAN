# MIZAN Security — الهندسة العكسية للأنظمة الأقوى

> هدف هذه الوثيقة ليس تقليد المنافسين، بل انتزاع أقوى أفكارهم وبناؤها في محرك
> واحد أخف وأسرع — بأسلوب MIZAN: قراءة فقط، بلا تبعيات ثقيلة، بمساءلة موثقة.

## 1. المشهد: التشتت هو المشكلة، لا الحل

الشركات القوية لا تستخدم أداة واحدة — بل عدة أدوات لا تتوقف عن التضخم:

- متوسط الفرق الأمنية يشغّل **5.3 أدوات أمنية منفصلة**، و**97% منها يخطط
  للتوحيد خلال عام** (Cycode 2026).
- المنصات الموحدة حققت **ROI بنسبة 101% مقابل 28%** للأدوات المفتتة
  (دراسة اقتصاديات توحيد AppSec).
- أزمنة الفحص للمنافسين الكبار: Semgrep ‏30 ثانية–5 دقائق، Snyk ‏1–5 دقائق،
  SonarQube ‏5–30 دقيقة، CodeQL ‏10–60 دقيقة. العمق بطيء دائماً تقريباً.
- السبب الأول لتخلي الفرق عن الماسحات ليس ضعف الكشف بل **إجهاد التنبيهات**
  (false positives بلا سياق delta).

## 2. مصفوفة الهندسة العكسية — ما نأخذه من كل نظام قوي

| النظام القوي | فكرته الأقوى | ما بُني في MIZAN Security | الحالة |
|---|---|---|---|
| **CodeQL** | فحص تفاضلي (baseline) يُقارن بالحالة المرجعية | `mizan baseline` + بصمات sha256 + بوابة على **الجديد فقط** | ✅ Q2 |
| **Semgrep** | سرعة CI وتعليقات PR فورية | full-scan متوازٍ (`--jobs`) + تعليق آلي على الـ PR عبر artifact | ✅ Q1/Q2 |
| **Snyk** | وصول SCA عميق + اقتراح ترقيات | تكامل OSV.dev بطلبات مجمعة وذاكرة تخزين ووضع offline + `mizan fix` ببوابة تحقق | ✅ v0.2 |
| **GHAS** | الوحدة على منصة واحدة (SAST+SCA+Secrets) | محرك واحد: 21 وحدة و14 أمراً تغطي كود/أسرار/تبعيات/CI/مخاطر تغيير | ✅ Q2 |
| **SonarQube** | استضافة ذاتية مجانية | تشغيل محلي كامل بلا سحابة ولا حساب | ✅ منذ البداية |
| **Checkmarx** | ارتباط النتائج عبر الأنواع (SAST/SCA/IaC) | `collect_findings` تجمع كل النتائج شجرياً في تقرير واحد يُقيد مركزياً | ✅ Q2 |
| **Semgrep/CodeQL** | بوابة عتبات جدية تكسر البناء | `mizan scan --gate critical,high` مع توحيد مفردات الخطورة عبر كل الوحدات | ✅ Q2 |

## 3. ما لا نكرره عمداً

1. **لا وكيل سحابي إلزامي** — الفحص المحلي أولاً، الشبكة اختيارية (OSV).
2. **لا قواعد مغلقة** — الماسحات مدمجة وقابلة للقراءة، والبصمات موثقة الصيغة.
3. **لا تنفيذ لكود المُفحوص** — قراءة فقط حرفياً؛ الإصلاح عبر worktree معزول
   وبوابة تحقق بالاختبارات.
4. **لا إجهاد تنبيهات** — خط الأساس يمتص المعروف، والبوابة تُفشل الجديد
   الحرج/العالي فقط.
5. **لا تكديس تبعيات** — تبعيتان فقط (PyYAML، tomli القديم)؛ التوازي من
   المكتبة القياسية.

## 4. مبرهنة التميز: أخف + أسرع + أقوى في آن واحد

- **أخف:** تثبيت واحد `pip install -e .` بلا سلاسل أدوات خارجية إلزامية.
- **أسرع:** الماسحات السبعة تعمل تزامنياً — زمن الحائط = أبطأ ماسح، لا مجموعها؛
  وطلبات OSV مجمعة (طلب واحد لأي عدد من التبعيات) بذاكرة TTL.
- **أقوى:** بوابة عتبات موحدة + خط أساس تفاضلي + سجل مساءلة (Ledger) + SARIF
  2.1.0 جاهز لـ GitHub code scanning + بوابة إصلاح مُتحقق منها.

## 5. خارطة ما بعد Q2 (مسودة Q3)

- ماسح أسرار مدمج بقواعد أنماط مخصصة (لا الاعتماد على أدوات خارجية فقط).
- ملفات تجاهل داخل الكود (`# mizan: ignore`) تُرحّل إلى البصمات تلقائياً.
- توازي مستوى الملفات في `analyzer` عبر عمليات (process pool) للمستودعات الضخمة.
- وضع `mizan watch` للفرق النشطة: فحص تفاضلي على كل commit.
