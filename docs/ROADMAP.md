## P2 — التالي (كل بند بحالات قبول مختبَرة قبل النشر)

1. **أتمتة PR الإصلاح** — `mizan repair --forge-pr`: فرع معزول ← دفع ←
   فتح PR عبر API بتوكن يوفره المستخدم صراحة؛ الافتراضي يبقى dry-run
   والقرار للإنسان؛ الشجرة المفحوصة لا تُمس أبداً.
2. **تتبع OSV الأسرع** — جلب دلتا دوري، ذاكرة سلبية أذكى، وتحذير تقادم
   الكاش ظاهر في التقرير.

3. **فجوة Go المُقاسة: الإسناد القصير `:=` يفلت من كشف الأسرار** — اكتُشفت في دورة الفحص الميداني 2026-11-08 وأُكّدت تجريبياً على المحرك المحلي: أنماط `hardcoded-secret-candidate` (`SECRET_PATTERN` / `SECRET_PATTERN_BARE`) تعتمد حرف إسناد واحد `[:=]` لا يستطيع مطابقة رمز Go ثنائي الحرف `:=` (short variable declaration). القياس: `password := "..."` في ملف `.go` يُنتج **صفر نتائج** بينما الشكل `password = "..."` نفسه يُطلق القاعدة — سالبة كاذبة (فرصة ضائعة، لا ضجيج). الإصلاح المرشح: بديل `(?::|=)` في موضع الإسناد + حالات إيجابية لـ`:=` وسلبية للتعليقات + تمرير المجموعات الذهبية كاملة قبل النشر.

منجز من هذه القائمة سابقاً: **`mizan portfolio`** (كان البند 2) —
أُنجز في 0.12.0 بتقرير HTML مجمّع ذاتي الاحتواء بتزدوج بصمة البوابة.

## P3 — بحثي (بلا جدول زمني)

1. Taint عبر الملفات بحد أقصى (bounded) على أنماط source→sink شائعة
   (SQL / SSRF / مسارات) مع قياس زمن معلن لكل مستودع.
2. Reachability عبر استدعاءات (call-graph ثنائي المستوى) وجدول أسماء
   مستعارة أكبر مبني على بيانات حقيقية موثقة.
3. خرائط امتثال (ISO 27001 / SOC 2 / PCI-DSS) فوق نتائج full-scan —
   طبقة عرض للاستخدام الداخلي، لا ادعاء شهادة.

## ما لن نفعله (صراحة)

- **قاعدة ثغرات ملكية**: لا بيانات نملكها ولا فرق بحث — ادعاؤها كذبة.
- **منصة GRC سحابية كاملة**: خارج هوية ميزان كأداة CLI خفيفة؛ نتكامل
  مع المنصات القائمة عبر SARIF 2.1.0 وJSON بدل منافستها.

ومؤجَّل صراحةً خلف بوابة P1 (حَكْم مواقع FP الـ 456 ثم تقرير Taint على
20 مستودعاً). القاعدة الحاكمة باقية: لا عائلات قواعد جديدة قبل إغلاق البوابتين.

2. عائلة قواعد مرشحة (لاحقاً — وكل قاعدة تمرّ ببوابة 0-FP على 20 مستودعاً):

3. OWASP LLM Top 10: إطار مرجعي لوثيقة `OWASP_LLM_PARITY.md` مستقبلاً —

   المستقل لملفاتها (`config.json`، `modeling_*.py`) مجال قيمة حقيقي لقياس P1.3.
5. يُضاف لقائمة «ما لن نفعله»: فحص LLM وقت التشغيل (مجال Garak/0DIN)،

## مُدخل استراتيجي مؤجل — «لا تنافس Semgrep، تخصّص» (سُجل 2026-11-08)

خلاصة تحليل الأعمدة الستة لبناء SAST جاد — مرجع بعيد المدى، لا عمل جارٍ:
(1) محلل نحوي متعدد اللغات عبر Tree-sitter، (2) محرك قواعد YAML، (3) Taint
داخل-الإجراء ثم عبر-الإجراءات، (4) تحليل عبر-الملفات (symbol table +
call graph للنداءات المباشرة مع توثيق قيود الديناميكية)، (5) أداء تزايدي،
(6) منظومة تبني (SARIF كامل / GitHub Action / إضافة محرر). فجواتنا الحالية
مقيسة: Python-ast فقط، قواعد مبرمجة، Taint PoC داخل-الملف، لا cross-file.

**ملاحظة حاكمة**: دمج Tree-sitter يعني أول اعتمادية خارجية في MIZAN —
يخالف قاعدة «لا تبعيات» الحالية ويحتاج قرارًا صريحًا وبوابة تقدير خاصة به،
لا يُنفذ بصمت. الأولوية الباقية بلا تغيير: بوابة FP للفجوات المقيسة ثم
تقرير Taint على 20 مستودعًا.

الاتجاه المعتمد تأطيريًا: **التخصص لا المنافسة** — أمان الذكاء الاصطناعي +
التوطين + الشفافية الصفرية، لا «Semgrep مصغر». وأطروحة صاحب القرار محفوظة
حرفيًا: أدوات الجيل السابق بُنيت في عهد لا ذكاء فيه — ميزة الجيل التالي
تبدأ من عهد الذكاء.
